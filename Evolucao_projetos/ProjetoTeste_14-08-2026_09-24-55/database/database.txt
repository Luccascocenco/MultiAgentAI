Com base na proposta de arquitetura apresentada, aqui está um exemplo de como pode ser estruturado o banco de dados para o sistema de hamburgueria:

```sql
CREATE DATABASE hamburgueria;

USE hamburgueria;

CREATE TABLE clientes (
  id INT PRIMARY KEY,
  nome VARCHAR(255),
  email VARCHAR(255) UNIQUE,
  senha VARCHAR(255)
);

CREATE TABLE pedidos (
  id INT PRIMARY KEY,
  cliente_id INT,
  data_hora DATETIME DEFAULT CURRENT_TIMESTAMP,
  total DECIMAL(10,2),
  FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

CREATE TABLE hamburguerias (
  id INT PRIMARY KEY,
  nome VARCHAR(255),
  preco DECIMAL(10,2),
  descricao TEXT
);

CREATE TABLE adiciones (
  id INT PRIMARY KEY,
  nome VARCHAR(255),
  preco DECIMAL(10,2),
  descricao TEXT
);

CREATE TABLE bebidas (
  id INT PRIMARY KEY,
  nome VARCHAR(255),
  preco DECIMAL(10,2),
  tipo VARCHAR(255)
);

CREATE TABLE pedidos_hamburguerias (
  pedido_id INT,
  hamburgueria_id INT,
  FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  FOREIGN KEY (hamburgueria_id) REFERENCES hamburguerias(id)
);

CREATE TABLE pedidos_adiciones (
  pedido_id INT,
  adicao_id INT,
  FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  FOREIGN KEY (adicao_id) REFERENCES adiciones(id)
);

CREATE TABLE pedidos_bebidas (
  pedido_id INT,
  bebida_id INT,
  FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  FOREIGN KEY (bebida_id) REFERENCES bebidas(id)
);

CREATE TABLE inventarios (
  id INT PRIMARY KEY,
  produto VARCHAR(255),
  quantidade INT
);

CREATE TABLE pedidos_inventario (
  pedido_id INT,
  produto_id INT,
  quantidade INT,
  FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  FOREIGN KEY (produto_id) REFERENCES inventarios(id)
);
```

Esse banco de dados inclui as seguintes tabelas:

*   `clientes`: armazena informações dos clientes, incluindo o ID, nome, email e senha.
*   `pedidos`: armazena informações dos pedidos, incluindo o ID, cliente ID, data e hora do pedido e total.
*   `hamburguerias`, `adiciones` e `bebidas`: armazenam informações das hamburguerias, adições e bebidas, respectivamente, incluindo o ID, nome, preço e descrição.
*   `pedidos_hamburguerias`, `pedidos_adiciones` e `pedidos_bebidas`: relacionam os pedidos com as hamburguerias, adições e bebidas, respectivamente. Isso permite que os pedidos sejam associados às opções de cada pedido.
*   `inventarios`: armazena informações do inventário, incluindo o ID, produto e quantidade.
*   `pedidos_inventario`: relaciona os pedidos com as quantidades dos produtos no inventário. Isso permite que os pedidos sejam atualizados conforme as quantidades dos produtos mudam.

Esse banco de dados é uma base sólida para o sistema de hamburgueria, permitindo a armazenamento e gestão eficiente das informações.
